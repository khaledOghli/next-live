Every export is a **named** binding, never a property on a parent object.
Across the RSC boundary a Server Component receives a *client reference*, so
`Live.Preview` would resolve to `undefined`.

<CodeBlock
  title="Entry points"
  code={`import { LiveProvider, LivePreview, LiveFileTabs, defineLoader } from 'next-live';
import { LiveEditor } from 'next-live/editor';          // optional peer: prism-react-renderer
import { LiveConsole } from 'next-live/console';        // console panel
import { LiveSandboxRoot } from 'next-live/sandbox';    // only on the sandbox page
import { precompile, validateSnippets } from 'next-live/server'; // server only`}
/>

| Entry | Contains | Why it is separate |
|---|---|---|
| `next-live` | Provider, preview, error, file tabs, hooks, registry, engine | This is the main entry. |
| `next-live/editor` | `<LiveEditor>` and the `FormatFn` types | The only thing needing `prism-react-renderer`, an **optional peer** you must install yourself. A preview-only page pays 16.1 KB instead of 97.2 KB. |
| `next-live/console` | `<LiveConsole>`, `useLiveConsole`, value formatting helpers | Only pages that show console output need the panel and its value inspector. |
| `next-live/sandbox` | `mountSandbox`, `<LiveSandboxRoot>` | Used only on the sandbox page. It carries its own copy of the compiler. |
| `next-live/server` | `precompile`, `precompileFiles`, `validateSnippet`, `validateSnippets`, `validateFiles` | Imports Sucrase statically, must never reach the client bundle. |
| `next-live/prettier` | `createPrettierFormatter` | Loads Prettier on the first format. `prettier` is an **optional peer** you must install yourself. |

### Formatting

`format` takes a `FormatFn`, `(code: string, ctx: FormatContext) => FormatResult`.
`FormatContext` is `{ language, cursorOffset }`, and a `FormatResult` is the new
code, or `{ code, cursorOffset? }` so the caret lands in the right place, either
directly or as a promise. [`createPrettierFormatter`](#createprettierformatter)
returns one ready to use.

### Standalone, without a provider

`<LiveEditor>` normally takes its code from the surrounding `<LiveProvider>` and
sends edits back to it. Pass `code` and it works on its own, which is how a page
shows a highlighted snippet it is not running:

<CodeBlock
  title="A highlighted snippet with no provider"
  code={`// Read-only: no onChange, so there is nowhere to write an edit.
<LiveEditor code={source} language="tsx" />

// Editable, driven by your own state.
<LiveEditor code={code} onChange={setCode} />`}
/>

With neither a provider nor `code`, the editor throws rather than rendering
empty.

<Callout variant="info" title="Keyboard access">
Tab inserts spaces, because an editor that moves focus on Tab cannot be typed
into. **Press Escape, then Tab, to move focus out**, the same convention
CodeMirror and Monaco use. The editor announces this through `aria-keyshortcuts`
and a visually-hidden description, and paints a focus ring while focused, so it
satisfies WCAG 2.1.2 (No Keyboard Trap) and 2.4.7 (Focus Visible). Any other
keystroke re-arms indentation, so Escape only ever releases the very next Tab.
</Callout>

`LiveEditorRenderProps` exposes `code`, `onChange`, `language`, `error`,
`errorLine`, and `errorColumn`, plus `diagnostics`, `selection` and
`onSelectionChange` when the host provides them. That is everything a
third-party editor needs:

<CodeBlock
  title="Swapping in a different editor"
  code={`<LiveEditor
  renderEditor={({ code, onChange, language, errorLine }) => (
    <CodeMirror value={code} onChange={onChange} lang={language} highlightLine={errorLine} />
  )}
/>`}
/>

<ApiEntry name="useLiveContext" kind="hook" from="next-live" signature="function useLiveContext(): LiveContextValue">

Reads the surrounding `<LiveProvider>`, for custom editors, toolbars, or status
indicators. **Throws if called outside a provider.** Returns every
`useLiveRunner` field plus `props`, `language`, `fallback`,
`reportRuntimeError`, and `formatError` when the provider has one.

Under `<LiveProvider sandbox>` it also returns `sandbox`, with the connection
`status` (`connecting`, `ready`, `unresponsive` or `failed`) and a `reload()`
function. `Component` and `element` stay `null` there, because the snippet runs
in the iframe.

</ApiEntry>

export function CompileStatus() {

  if (error) return <span className="text-destructive">Failed</span>;
  return <span>Compiled #{compileId}</span>;
}`}

## Registry helpers

<ApiEntry name="defineLoader" kind="function" from="next-live" signature="function defineLoader(load: ModuleLoader): ModuleLoader">

Marks a function as a lazy loader rather than as the module value itself.
Without it, a registered component function would be indistinguishable from a
loader. **This is the default way to register a module**; it keeps your own
dependencies out of the page bundle.

The loader receives the imported specifier, which is what prefix entries need.

</ApiEntry>

<CodeBlock
  code={`// Exact match, the specifier can be ignored.
'@app/store': defineLoader(() => import('@/lib/store')),

// Prefix entry (key ends in '/'), one loader serves the whole subtree.
'big-lib/': defineLoader((specifier) => import(\`big-lib/\${specifier.slice(8)}\`)),`}
/>

<ApiEntry name="defineModule" kind="function" from="next-live" signature="function defineModule(shape: { default?: unknown; exports?: Record<string, unknown> }): NormalizedModule">

Builds an explicit module record. A registered object with its own `default` key
is normally unwrapped; use this when the whole object *is* the default export.
`default` and `exports.default` address the same slot.

</ApiEntry>

<ApiEntry name="createRegistry" kind="function" from="next-live" signature="function createRegistry(...groups: ModuleRegistry[]): ModuleRegistry">

Merges registry groups, later groups winning. Warns in development when two
groups define the same key, which is how you catch a silent override.

</ApiEntry>

<ApiEntry name="registryFromGlob" kind="function" from="next-live" signature="function registryFromGlob(glob: GlobResult, toSpecifier: (path: string) => string | null): ModuleRegistry">

Converts `import.meta.glob`'s lazy result into a registry of loaders.
`toSpecifier` maps a file path to the specifier authors write; return `null` to
omit a file.

</ApiEntry>

<ApiEntry name="builtinModules" kind="constant" from="next-live" signature="const builtinModules: ModuleRegistry">

The always-registered map: `react`, `react/jsx-runtime`, and
`react/jsx-dev-runtime`. Your `modules` merge **over** these, so a React shim can
still be substituted. `react-dom` is deliberately absent, register it
explicitly if you need it.

</ApiEntry>

| Export | Purpose |

## Engine

Lower-level exports, for a custom scheduler or for compiling outside React.

<ApiEntry name="compile" kind="function" from="next-live" signature="function compile(input: CompileInput | CompileFilesInput): Promise<CompileResult>">

Transpile, resolve every import, then evaluate. Takes a `CompileInput`, or a
`CompileFilesInput` with `files` and `entry` instead of `code`. Returns
`{ renderable, via, code, imports }`, plus `entry` and `files` for a multi-file
snippet. Throws if the snippet produced nothing renderable.

</ApiEntry>

<ApiEntry name="compileModule" kind="function" from="next-live" signature="function compileModule(input: CompileInput | CompileFilesInput): Promise<CompileModuleResult>">

The same pipeline, returning `{ exports, code, imports }` with no component
required.

</ApiEntry>

<ApiEntry name="transpile" kind="function" from="next-live" signature="function transpile(source: string, options?: TranspileOptions, transform?: TransformFn): Promise<TransformResult>">

Source → CommonJS. No evaluation, no module resolution.

</ApiEntry>

<ApiEntry name="preloadTranspiler" kind="function" from="next-live" signature="function preloadTranspiler(): void">

Starts fetching the lazily-loaded Sucrase chunk, so the first compile does not
pay for the download. It returns straight away and never throws; a failed
download is reported by the compile that needs it. Call it when you know an editor is about to open.

</ApiEntry>

<ApiEntry name="precompiledTransform" kind="function" from="next-live" signature="function precompiledTransform(result: TransformResult): () => TransformResult
function precompiledTransform(results: Readonly<Record<string, TransformResult>>): TransformFn">

Wraps a server-precompiled result as a `transform`, so the client never loads
Sucrase at all. The second form takes the `files` record from `precompileFiles`
and finds each file's output by its path. Exported from the **client** entry, importing it from
`next-live/server` would pull the transpiler into your page.

</ApiEntry>

<ApiEntry name="setTranspiler" kind="function" from="next-live" signature="function setTranspiler(module: typeof import('sucrase') | null): void">

Swaps the transpiler outright, or restores lazy loading with `null`. For tests and
custom backends. Experimental.

</ApiEntry>

<ApiEntry name="errorPosition" kind="function" from="next-live" signature="function errorPosition(error: Error | null | undefined): { line: number; column?: number; file?: string } | null">

Reads `{ line, column?, file? }` off a compile or runtime error, and returns `null`
when there is no position. This is what a custom editor uses to paint the
failing line. Pass it the `error` from `useLiveRunner` or `useLiveContext`
directly; a `null` error is handled.

</ApiEntry>

<ApiEntry name="serializeError" kind="function" from="next-live" signature="function serializeError(error: unknown): SerializedError">

Turns any error into plain data. `rehydrateError(data)` turns it back into a real
next-live error class, so `instanceof` checks keep working. Used for errors that
cross into or out of the sandbox iframe.

</ApiEntry>

<ApiEntry name="preloadSandboxHost" kind="function" from="next-live" signature="function preloadSandboxHost(): void">

Starts downloading the sandbox host code before a `<LiveProvider sandbox>` needs
it, for example when the visitor hovers a "Run" button.

</ApiEntry>

<ApiEntry name="createRenderBudget" kind="function" from="next-live" signature="function createRenderBudget(options?: RenderBudgetOptions): () => void">

The render-loop breaker. A fresh budget is created per compile, so fixing a
runaway snippet clears a tripped breaker without a page reload.

</ApiEntry>

<ApiEntry name="normalizeModule" kind="function" from="next-live" signature="function normalizeModule(value: unknown): NormalizedModule">

The interop normalisation applied to every registry value: maps an arbitrary
object, function, or namespace onto `default` plus named exports.

</ApiEntry>

<ApiEntry name="createRequire" kind="function" from="next-live" signature="function createRequire(resolved: ResolvedModules): (specifier: string) => NormalizedModule">

The synchronous `require` shim handed to compiled snippets, over the
`ResolvedModules` that `resolveModules` produces. It must stay
synchronous: Sucrase emits `require()` at module top level, which cannot await.

</ApiEntry>

<ApiEntry name="resolveModules" kind="function" from="next-live" signature="function resolveModules(options: ResolveOptions): Promise<ResolvedModules>">

Resolves every specifier a snippet needs *before* evaluation, which is why
async loaders work at all despite `require()` being synchronous. `ResolveOptions`
takes `registry`, `specifiers`, `resolveSubpaths` and `signal`.

</ApiEntry>

<ApiEntry name="precompile" kind="function" from="next-live/server" signature="function precompile(source: string, options?: TranspileOptions): PrecompileResult">

Transpiles to exactly the same CommonJS the browser path produces, so a

Validates many at once and returns **only the failures**, so a CI step can

</ApiEntry>

<ApiEntry name="precompileFiles" kind="function" from="next-live/server" signature="function precompileFiles(files: Readonly<Record<string, string>>, options?: PrecompileFilesOptions): PrecompileFilesResult">

Precompiles every file of a multi-file snippet. Accepts `entry` plus the usual

## Errors

All extend `LiveError`, exported as `LiveErrorBase` so it does not collide with
the `<LiveError>` component. Every error has a readonly `code`, a `LiveErrorCode`,
which is the stable thing to branch on.

| Class | `code` | Raised when |
|---|---|---|
| `LiveCompileError` | `'COMPILE'` | Parse/transpile failure, or a CSP blocking `eval`. Carries `line` and `column`, plus `file` for a multi-file snippet. |
| `LiveRuntimeError` | `'RUNTIME'` | The snippet threw. Carries `line` and `column` where the stack can be mapped, plus `file` for a multi-file snippet. |
| `RenderLoopError` | `'RENDER_LOOP'` | The render-rate breaker tripped. `instanceof LiveRuntimeError` is true. |
| `ModuleNotFoundError` | `'MODULE_NOT_FOUND'` | An import specifier is not registered. Carries `specifier` and `available`, plus `importer` for a multi-file snippet. |
| `NoComponentError` | `'NO_COMPONENT'` | The snippet produced nothing renderable. |
| `TranspilerLoadError` | `'TRANSPILER_LOAD'` | Sucrase failed to load, usually a chunk-load failure. |
| `LiveSandboxError` | `'SANDBOX'` | Sandbox mode only, for the `reason` below. |

`line`, `column`, `file`, `importer` and `reason` are only present when they
apply, so a single in-page snippet's errors have exactly the properties they had
in 1.0.

<CodeBlock
  title="Painting the failing line"
  code={`if (error instanceof LiveRuntimeError && error.line !== undefined) {
  highlight(error.line, error.column);
}`}
/>

`LiveSandboxError` carries a `reason`, a `LiveSandboxErrorReason`:

| `reason` | Meaning |
|---|---|
| `'invalid-config'` | `sandbox.src` or `allowedOrigins` is not valid. |
| `'same-origin-refused'` | `allowSameOrigin` was set for a sandbox on the page's own origin. |
| `'load-failed'` | The frame could not be reached. |
| `'handshake-timeout'` | The sandbox page did not answer in time. |
| `'origin-rejected'` | The sandbox refused this page's origin. |
| `'protocol-mismatch'` | The host page and the sandbox run incompatible next-live versions. |
| `'unresponsive'` | The sandbox stopped answering, usually a snippet stuck in a loop. |
| `'restart-limit'` | It froze too often and was not restarted again. |
| `'props-not-cloneable'` | `props` held something that cannot be copied into the iframe. |

A snippet that throws while rendering is caught by the boundary inside
`<LivePreview>` and surfaced through `<LiveError>`; the page itself never goes
down:
