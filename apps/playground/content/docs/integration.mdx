An end-to-end walkthrough for running snippets that live outside your build,
wherever they come from and whoever writes them.

## Architecture

Only three things have to be true. Everything else is your application's
existing shape:

<CodeBlock
  title="Data flow"
  language="text"
  code={`1. STORE
   the snippet source lives somewhere you already control
   (database row, CMS field, file in your repo)
                        │
                        │   2. SERVE
                        │   your app hands it to the client
                        │   as a plain string
                        ▼
            <LiveProvider code={source}>
                        │
                        │   3. RUN
                        │   compiled in the browser
                        ▼
               a live React component`}
  caption="Nothing compiles on the server. The snippet travels as a string and becomes a component in the browser."
/>

<Callout variant="info" title="The names below are illustrative">
  This guide uses a database, an admin UI, and a `/api/apps/[id]` route because
  a concrete example is easier to follow than an abstract one, but next-live
  has no opinion about any of them. It never fetches anything itself. If your
  snippets are Markdown frontmatter, rows in Postgres, or a constant in the
  repo, keep whatever you already have: the only requirement is that `code` is
  a **string** by the time it reaches `<LiveProvider>` in the browser.
</Callout>

  {
    title: 'Decide your SDK surface first',
    children: (

        <p>
          Pick stable namespaces before you write any code. These become a public

        <CodeBlock
          language="text"
          title="The contract"

@app/ui       buttons, cards, layout primitives
@app/format   dates, currency, numbers
@app/data     fetch helpers`}
        />
        <p>
          Keep the surface small and boring. Every export is something you have
          to keep working.
        </p>
      </>
    ),
  },
  {
    title: 'Build the registry from small files',
    children: (
      <>
        <p>
          One file per domain, composed in an <code>index.ts</code>. This beats a
          literal inlined on <code>LiveProvider</code>: the groups are testable,
          and <code>createRegistry</code> warns in development when two of them
          claim the same key.
        </p>
        <CodeTabs
          files={[
            {
              name: 'lib/live-sdk/index.ts',
              highlight: '7-12',
              code: `import { createRegistry } from 'next-live';
import { formatModules } from './format-modules';
import { storeModules } from './store-modules';
import { uiModules } from './ui-modules';
import { vendorModules } from './vendor';

export const liveModules = createRegistry(
  vendorModules,
  uiModules,
  formatModules,
  storeModules,
);`,
            },
            {
              name: 'ui-modules.ts',
              code: `import { defineLoader } from 'next-live';
import type { ModuleRegistry } from 'next-live';

export const uiModules: ModuleRegistry = {
  '@app/ui': defineLoader(() => import('./modules/ui')),
};`,
            },
            {
              name: 'store-modules.ts',
              code: `import { defineLoader } from 'next-live';
import type { ModuleRegistry } from 'next-live';

export const storeModules: ModuleRegistry = {
  '@app/store': defineLoader(() => import('./modules/store')),
};`,
            },
            {
              name: 'modules/ui.ts',
              code: `// A thin re-export, so the specifier's surface is explicit and reviewable

export { Button } from '@/components/ui/button';

        />

  },

          A snippet is TSX source text, not a file path. You can author{' '}

        </p>
        <CodeBlock

  name: 'Revenue widget',
  source: "import { Card } from '@app/ui';\\n\\nexport default function App() { … }",

    title: 'Serve it behind whatever auth you already have',
    children: (
      <>
        <p>
          If the source is already in your bundle or read at build time, skip

          HTTP, the route is an ordinary authenticated endpoint:
        </p>
        <CodeBlock
          title="app/api/apps/[id]/route.ts"
          highlight="2-5"
          code={`export async function GET(request: Request, { params }) {
  const session = await auth(request);
  if (!session) {
    return Response.json({ error: 'unauthorized' }, { status: 401 });
  }

  const app = await db.apps.find(params.id);
  if (!app) return Response.json({ error: 'not found' }, { status: 404 });

  return Response.json({ id: app.id, source: app.source });
}`}
        />

          Whoever can POST a snippet can run JavaScript on your site, as your
          users, with their cookies. Read access controls who sees an app; write

    title: 'Render it, and persist edits',
    children: (
      <>
        <p>
          <code>onCodeChange</code> fires only for edits made <em>inside</em> the
          runner, never when the <code>code</code> prop changes from outside. That
          is what makes it safe to save from: it cannot echo your own writes back
          at you in a loop.

        <CodeBlock
          title="app/apps/[id]/AppRunner.tsx"
          highlight="14-16"
          code={`'use client';

import { LiveProvider, LivePreview, LiveError } from 'next-live';
import { LiveEditor } from 'next-live/editor';
import { liveModules } from '@/lib/live-sdk';

export function AppRunner({ id, source, user, canEdit }) {
  return (
    <LiveProvider
      code={source}
      modules={liveModules}
      props={{ user }}
      filePath={\`app-\${id}.tsx\`}
      onCodeChange={
        canEdit ? (next) => saveDraft(id, next) : undefined
      }
      fallback={<Skeleton className="h-80 w-full" />}
    >
      {canEdit && <LiveEditor />}
      <LivePreview />
      <LiveError />
    </LiveProvider>
  );
}`}

## See it running

The [Apps shell demo](/apps) in this repo implements exactly this pattern:
sidebar tabs, API-fetched snippets, shadcn components through `@app/ui`, and a
store shared with the host page through `@app/store`.

<Callout variant="info" title="Code is always a string">
  Whether it comes from a database, an API, or a template literal in your repo,
  next-live only ever receives source text: <code>{'code={source}'}</code> for
  one file, or <code>{'files={{ path: source }}'}</code> for a
  <Link href="/docs/multi-file">multi-file snippet</Link>. It never reads
  paths from disk.
</Callout>
