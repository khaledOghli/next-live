## There is no npm in the browser

Your page bundle contains only what **you** imported when it was built. A snippet saying `import _ from 'lodash'` cannot conjure lodash into existence — you hand it over via the `modules` prop:

<CodeBlock code={`<LiveProvider
  code={source}
  modules={{
    '@app/store': defineLoader(() => import('@/lib/store')),
  }}
/>`} />

If the specifier is not registered, the snippet fails with a clear error naming it.

This replaces react-live's flat `scope` object, where every helper had to be injected as a global and `import` was impossible.

## The key is just a string

A registry key does not have to be a real package name. Pick names that read like a deliberate SDK:

<CodeBlock code={`modules={{
  '@app/store':   /* … */,
  '@/store':      /* … */,
  'my-utils':     /* … */,
}}`} />

## Loaders vs values

**Loader (default):** code-split, fetched only when a snippet imports it.

<CodeBlock code={`'@app/store': defineLoader(() => import('@/lib/store'))`} />

**Value:** simpler, but always in your page bundle.

<CodeBlock code={`import * as store from '@/lib/store';
modules={{ '@app/store': store }}`} />

Use loaders. A registry of 300 loaders costs nothing at runtime — only specifiers that appear in the compiled snippet are resolved.

## Every import form works

| Snippet writes | Gets |
|---|---|
| `import ui from '@app/ui'` | default export, or the module itself |
| `import { Button } from '@app/ui'` | named export |
| `import * as ui from '@app/ui'` | namespace |
| `import '@app/ui'` | side effects only |
